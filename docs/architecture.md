# 初期アーキテクチャ

## 原則

AIは企業を発見・創作する情報源として扱わず、取得済みページの分類、要約、根拠抽出に限定して使用します。URL到達性、連絡先抽出、重複排除、根拠照合は決定的なプログラムで行います。

## 処理フロー

1. 商材、営業目的、対象地域、理想顧客像を入力する
2. 検索サービスや信頼できるディレクトリから候補URLを取得する
3. URLを正規化し、同一ドメインを重複排除する
4. 静的HTTP取得を試す
5. 必要な場合だけヘッドレスブラウザでレンダリングする
6. 会社名、所在地、商品、業態、連絡先を抽出する
7. AIが取得済み本文から適合性と根拠を構造化出力する
8. 根拠文が取得本文に実在することをプログラムで再確認する
9. `accepted`、`review`、`rejected`、`blocked` に分類する
10. 根拠付きのCSVまたはスプレッドシートを出力する

## ブラウザ取得の段階

1. 通常のHTTP取得
2. Cloudflare Browser Runまたは標準Playwright
3. 許可された対象に限る追加ブラウザランナー
4. 取得不能の場合は `blocked` として保存

追加ブラウザは、CAPTCHAやアクセス制限を回避する目的では使用しません。robots.txt、サイト利用条件、アクセス頻度を尊重します。

## AI構成

- 初期Skill版: Codexの現在の実行環境を利用
- アプリ版: Gemini、OpenAI、Claude、Workers AIなどを交換可能なアダプターとして実装
- 通常判定: 高速・低コストモデル
- 境界ケース: 上位モデルまたは人間による確認
- 最終合否: AI出力だけでなくルールエンジンが決定

## 必須の出力項目

- `company_name`
- `canonical_url`
- `final_url`
- `country`
- `company_type`
- `product_fit`
- `fit_score`
- `evidence_text`
- `evidence_url`
- `email`
- `email_source_url`
- `contact_form_url`
- `site_status`
- `verification_status`
- `rejection_reason`
- `checked_at`

## フェーズ1の範囲

- 1つの商材と1つの対象市場で試験する
- 20〜50社程度を調査する
- 採用企業すべてに根拠URLと根拠文を付ける
- 人間による正解ラベルを保存する
- 誤採用率、連絡先取得率、1社あたり処理時間を測定する

## フェーズ1では行わないこと

- 自動営業メール送信
- 問い合わせフォームの自動送信
- CAPTCHA回避
- 推測メールアドレスの出力
- 法人登記確認の完全自動化
- 大量並列クロール
