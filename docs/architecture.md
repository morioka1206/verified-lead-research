# 初期アーキテクチャ

## 原則

AIは企業を発見・創作する情報源として扱わず、取得済みページの分類、要約、根拠抽出に限定して使用します。URL到達性、連絡先抽出、重複排除、根拠照合は決定的なプログラムで行います。

## 処理フロー

1. 商材、営業目的、対象地域、理想顧客像を入力する
2. CodexまたはClaude CodeのWeb検索で候補URLを取得する
3. URLを正規化し、公式ドメイン単位で重複排除する
4. 静的HTTP取得を試し、JavaScriptが必要な場合だけローカルPlaywrightを使う
5. 1社につき重要ページを最大5ページ取得する
6. プログラムが会社名候補と公開メールを抽出し、明確な問い合わせフォームが通常の確認範囲にあれば任意で記録する
7. AIが取得済み本文から会社概要と3種類の証拠候補を構造化出力する
8. プログラムが根拠文と根拠URLを取得本文へ照合する
9. `accepted`、`review`、`rejected`、`blocked` を決定する
10. 合格30社の日本語CSVと、全候補の監査JSONを出力する

## ブラウザ取得の段階

1. 通常のHTTP取得
2. ローカルPlaywrightとChromium
3. 取得不能の場合は `blocked` として保存

CAPTCHAやアクセス制限は回避しません。robots.txt、サイト利用条件、アクセス頻度を尊重します。

問い合わせフォーム探しは補助機能です。最大5ページの通常確認を越えてクリック探索せず、見つからなくても会社の合否には影響させません。

## AI構成

- 初期Skill版: CodexまたはClaude Codeの現在の実行環境を利用
- アプリ版: Gemini、OpenAI、Claude、Workers AIなどを交換可能なアダプターとして実装
- 通常判定: 高速・低コストモデル
- 境界ケース: 上位モデルまたは人間による確認
- 最終合否: 3種類の証拠をプログラムで照合して決定

## 必須の出力項目

- `company_name`
- `canonical_url`
- `final_url`
- `country`
- `company_type`
- `company_overview_ja`
- `claims`（商材・会社の役割・対象地域）
- `emails`
- `contact_forms`
- `verification_status`
- `rejection_reason`
- `checked_at`

## フェーズ1の範囲

- 1つの商材と1つの対象市場で試験する
- 最大100社を調査し、合格30社を作る
- 合格企業すべてに3種類の根拠URLと原文を付ける
- 人間による正解ラベルを保存する
- 誤採用率、連絡先取得率、1社あたり処理時間を測定する

## フェーズ1では行わないこと

- 自動営業メール送信
- 問い合わせフォームの自動送信
- CAPTCHA回避
- 推測メールアドレスの出力
- 法人登記確認
- 大量並列クロール
