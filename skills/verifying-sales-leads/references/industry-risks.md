# 業種・サイト別の難しさと実地メモ

この文書は、証拠付き営業リストを別の商材、業種、国へ広げる時に、同じ失敗を繰り返さないための記録です。

## 小学生でも分かる現在地

今の仕組みは、会社ごとに自分のホームページがあり、そこに商品、仕事の種類、活動地域が書かれている場合に強いです。

カフェ、コーヒー店、抹茶・和牛の輸入会社や卸会社では、実際のサイトを使って良い結果を確認できました。このツールが集めるのは、会社、本部、ブランド運営会社、メーカー、卸会社などの営業先です。マーケットプレイスの個別出店者やフランチャイズ各店舗は、最初から対象にしません。

新しい業種では、最初から大量に集めず、まず10社を人が確認します。間違い方を見てから、検索語、確認ページ、除外条件を調整します。

## 現在の検証範囲

| 対象 | 現在地 | 分かったこと |
|---|---|---|
| 抹茶の輸入・卸会社 | 一部実証済み | 公式サイトに商品と卸・輸入の説明がある企業では有効 |
| 和牛の輸入・卸会社 | 少量実証済み | 商品と卸売の証拠は取れるが、対象国の実拠点確認に注意が必要 |
| 米国のカフェ・コーヒー店・飲食店 | 50社で実証済み | メニューと店舗ページを優先すると精度が上がる |
| 工業用ネジの卸・販売会社 | タイで10社試験済み | 販売会社と自社製造会社の重なりが大きく、除外条件の確認が重要 |
| その他の製造業・機械販売 | 未実証 | 製品、代理店、導入先、保守会社を区別する設計が必要 |
| ホテル・小売チェーン | 未実証 | 本部と各店舗、購買権限の所在を区別する必要がある |
| B2Bサービス・SaaS | 未実証 | 商品名の言及だけでは利用企業・代理店・競合を区別しにくい |
| マーケットプレイス出店者 | 対象外 | 会社単位の営業リストではなく、個別出店者リストになるため扱わない |
| フランチャイズ各店舗 | 対象外 | 各店舗ではなく、必要なら本部・ブランド運営会社を営業先にする |
| SNSだけで営業する事業者 | 原則確認待ち | 公式サイトの3証拠を満たせず、なりすまし確認も難しい |
| 許認可・認証が重要な業種 | 条件付き | 営業候補なら公式サイト上の表示を確認し、法的な有効性まで必要なら公的名簿も確認する |

## 特に大きな懸念

### 1. 営業先の単位を会社・本部にそろえる

現在は公式ドメイン単位で重複を除きます。このため、営業先は会社、本部、ブランド運営会社などの組織単位にそろえます。

- マーケットプレイスの個別出店者は集めない
- フランチャイズ各店は集めず、必要なら本部を調べる
- 予約サイトやデリバリーサイトの掲載店舗を公式URLとして扱わない
- 親会社が複数ブランドを運営する場合は、どの組織へ営業するかを先に決める
- 一つの会社が複数ドメインを持つ場合は、同じ会社として重複確認する

検索結果にプラットフォーム出店ページや個別店舗ページが出ても、会社の独立した公式サイトまたは本部サイトへ移れない場合は合格にしません。

### 2. 商材の掲載と「買い手であること」は同じではない

サイトに抹茶や和牛があっても、今回の営業相手とは限りません。

- 仕入れ候補ではなく、同じ商品を卸す競合会社
- 商品を紹介しただけのブログ、ニュース、レシピサイト
- 過去の期間限定メニューだけが残っている店
- メニューはあるが、仕入れを本部が一括管理する加盟店
- 商材を販売しているが、業務用の仕入れ権限を持たない店舗

AIの `accepted` 判断を必須にし、証拠が3つあるだけで `review` や `rejected` を格上げしない現在のルールは、この問題への重要な防波堤です。ただし、業種ごとの「買い手の役割」を最初のヒアリングで具体化する必要があります。

### 3. 対象国の証拠が弱くなりやすい

次の情報だけでは、対象国で事業をしている証拠として不十分です。

- 英語のサイトがある
- 通貨を米ドルで表示する
- 世界向け、グローバルと書いてある
- 国名がブログや配送除外国の一覧に出る
- アクセスした人の地域に合わせて表示が変わる

住所、店舗、倉庫、配送対象、顧客、販売店など、キャンペーンで合意した市場活動の証拠が必要です。越境配送と現地拠点を同じ意味に扱いません。

### 4. 許認可・認証は「表示確認」と「法的確認」を分ける

保育園、医療、建設、運送、食品製造などでは、認可、許可、登録、認証が営業条件になることがあります。その場合は、通常の3証拠に加えて次を探します。

- 認可・許可・登録・認証の正式名称
- 認可番号、登録番号、認証番号
- 発行機関、認証機関
- 対象となる施設、商品、業務範囲
- 有効期限や更新日の表示
- 公的名簿・認証機関への公式リンク

営業候補を絞る目的なら、会社の公式サイトに必要な認可・認証が明記されていることを追加の確認項目にできます。ただし、それだけで現在の法的有効性を保証したとは書きません。法的な有効性が合否を左右する案件では、官公庁や認証機関の公的名簿を一次資料として確認する別工程が必要です。

現在のプログラムは、商材・会社の役割・対象市場の3種類を必須ゲートにしています。許認可・認証を機械的な第4の必須ゲートにする処理はまだ実装していないため、その業種を本格調査する前に10社で証拠形式を確認し、必要なら実装とテストを追加します。

### 5. 業種ごとに重要ページが違う

カフェではメニューと店舗一覧が重要でした。しかし、同じ優先順位を他業種へそのまま使うと重要な証拠を逃します。

| 業種 | 優先して確認したいページ |
|---|---|
| カフェ・飲食店 | ドリンクメニュー、店舗一覧、About、Contact |
| 輸入・卸 | Products、Brands、Wholesale、Distribution、Territory |
| 製造業 | Products、Industries、Capabilities、Distributors、Certifications |
| ホテル | Properties、Restaurants、Meetings、Procurement、Supplier情報 |
| 小売チェーン | Store locator、Brands、Categories、Vendor情報 |
| SaaS | Product、Customers、Partners、Integrations、Pricing、Security |
| 認可業種 | License、Accreditation、Certification、施設概要、公的名簿へのリンク |

新業種ではページ優先語を先に決め、10社の試験結果を見て追加します。

### 6. 公式サイトでも読み取れない情報がある

- PDFだけにメニューや商品カタログがある
- 地図部品の中にだけ店舗住所がある
- JavaScript実行後にだけ本文が表示される
- 地域選択、Cookie同意、年齢確認の後に表示される
- Bot対策、ログイン、CAPTCHAで取得できない
- 画像の中にだけメニューや連絡先が書かれている

JavaScriptページはPlaywrightで補えますが、PDF本文、埋め込み地図、画像OCR、ログイン必須ページは十分に対応していません。Bot対策やCAPTCHAは突破せず `blocked` または `review` にします。

### 7. 連絡先が営業窓口とは限らない

公開メールが見つかっても、予約、採用、顧客サポート、報道向けの場合があります。問い合わせフォームもJavaScriptで数回クリックしないと現れないことがあり、通常の5ページ確認だけでは見つけられません。

現在は公開されたメールだけを保存し、メールの目的を推測しません。問い合わせフォームは見つかった時だけ記録し、空欄でも会社を不合格にしません。将来、購買担当者や部署別連絡先まで必要になった場合は、会社確認とは別の調査工程に分けます。

### 8. 検索結果には偏りがある

Web検索は、検索対策が強い企業、大手、英語サイトを持つ企業を見つけやすくします。小規模な現地企業、現地語だけの企業、新しい会社は漏れる可能性があります。検索上位50社は、市場全体の代表標本ではありません。

国名、都市名、現地語、業界用語、買い手の言い方を変えた複数の検索を使います。大量案件では都市・州・国・企業種別ごとの偏りも確認します。

### 9. サイトがあることと現在営業中であることは同じではない

URLが開いても、会社が現在営業中とは限りません。古いメニュー、閉店した店舗、買収前のブランド、更新されていない会社サイトが残ることがあります。

確認日時は保存しますが、現在は法人登記、営業許可、SNSの最新投稿までは標準確認に含めません。「公式サイト上で確認できた会社」であり、「法的・営業上の存続を完全に証明した会社」ではありません。

### 10. 10社確認は全件精度の証明ではない

10社の抜き取り確認は、明らかな設計ミスを早く見つけるためのものです。難しい会社を意図的に混ぜるため、統計的な無作為抽出でもありません。10社中10社が正しくても、残りすべてが正しいとは断定しません。

9社以上が正しければ簡易チェック合格、8社以下なら20社または全件へ広げます。重要な営業、規制対象、高額案件では最初から全件確認を選びます。

### 11. CodexとClaudeで検索結果は完全一致しない

同じSkill、入力スキーマ、判定ルールは共有できますが、検索機能、利用できるブラウザ、モデルの判断が異なるため、候補会社の完全一致は保証できません。比較する時は、同じ候補URLを渡して最終判定と出力スキーマを比べます。

## 実際に難しかったことと対応記録

| 発見したこと | 起きた問題 | 対応 | 現在地 |
|---|---|---|---|
| AI判定と証拠ゲートの順序 | AIが競合として `review`／`rejected` にした企業を、3証拠だけで `accepted` に格上げした | AIの推薦が `accepted` の場合だけ合格可能にした | 対応・テスト済み |
| URL内の空白や日本語 | HTTP要求が例外になり、クロール全体が止まった | パスとクエリをエンコードし、HTTP例外を1社の失敗として扱った | 対応・テスト済み |
| 最後に一括保存 | 途中の例外で取得済み結果も失われた | 1社ごとにチェックポイント保存し、再実行時に続きから再開 | 対応・テスト済み |
| 同じ会社の再取得 | 古いクロール結果が使われることがあった | 後から渡した新しい結果を優先 | 対応・テスト済み |
| カフェのページ選び | 一般メニューや料理ページを先に読み、抹茶飲料を逃した | ドリンクメニュー、店舗一覧を優先 | 対応・カフェ向け |
| `Cafes` という店舗ページ | 店舗一覧として認識できなかった | カフェ向けページ語へ追加 | 対応・カフェ向け |
| 競合・デモ・移動販売 | 3証拠があっても営業対象として不適切な候補が混ざった | AIの対象適合判定、除外条件、人の重点確認を併用 | 一部対応 |
| 問い合わせフォーム | 通常取得だけでは見つからないサイトが多かった | 補助情報へ変更し、合否条件から外した | 仕様として整理済み |
| PDFメニュー | HTML本文に商品情報がなく証拠を取れない | 未対応課題として記録 | 未対応 |
| 埋め込み地図 | 店舗住所が地図部品にしかなく市場証拠を取れない | 未対応課題として記録 | 未対応 |
| 人の確認表 | 判定列と証拠列が営業利用時に邪魔になった | 営業リストと任意の品質確認表を分離 | 対応・テスト済み |
| タイのネジ販売会社検索 | 「製造・輸入・販売」を兼ねる会社が検索上位に多く、販売の証拠だけでは対象外企業が合格し得た | キャンペーンの除外条件を全候補で1項目ずつ記録し、未確認・該当・判断不能なら合格できない機械ゲートを追加 | 対応・テスト済み |
| 大手ホームセンター | 商品ページ、会社の業態、タイの所在地が別ページや別サブドメインに分かれ、1回の自動リンク探索で3証拠がそろわない場合があった | 商品URLを入口にし、About・Contact・店舗ページを優先。取得記録に入らない証拠は検索で見えても合格へ使わない | 一部対応・追加URL指定は未実装 |
| 公式サイトの仮メール | Wix等のテンプレート由来とみられる `info@mysite.com` が実在メールと一緒に抽出された | 推測メールと同様に、明らかなプレースホルダーを営業リストから除く必要がある | 未対応 |

## 新しい業種を始める前の確認表

次を決められない場合は、50社以上の本調査を始めず、10社の試験を行います。

1. **1社の単位**：会社、本部、ブランド運営会社のどれを1件と数えるか。個別出店者とフランチャイズ各店は対象外。
2. **公式URLの定義**：独立した会社サイトまたは本部サイトを使い、プラットフォーム掲載ページだけでは合格にしない。
3. **商材との関係**：販売、使用、製造、輸入、紹介のどれを合格にするか。
4. **買い手の役割**：誰が仕入れや契約を決める可能性があるか。
5. **対象市場の証拠**：住所、店舗、配送、顧客、販売代理店のどれを認めるか。
6. **除外条件**：競合、ブログ、ニュース、モールだけの掲載、閉店、移動販売など。
7. **重要ページ**：その業種では、どのページに商品・役割・地域が書かれるか。
8. **連絡先の期待**：代表メールでよいか、購買部署が必須か。必須なら別工程が必要か。
9. **許認可・認証**：必要な業種では、名称・番号・発行機関の表示でよいか、公的名簿確認まで必要か。
10. **人の確認範囲**：10社、20社、全件のどれがリスクに合うか。
11. **停止条件**：どの誤りが出たら本調査を止め、条件を直すか。

## 実地ログ

### 2026-09-26｜日本産業務用抹茶・米国・カフェ／飲食店

- 調査候補：85社
- 最終出力：50社
- 人の確認：50社すべてが確認表で「正しい」になり、URL切れはなかった。全体の質は高いと評価されたが、英語の細部を全件精読した確認ではない
- うまくいったこと：ドリンクメニューと店舗一覧を優先し、商材・会社の役割・対象地域の3証拠を確認
- 難しかったこと：英語の細部を全件精読する負担、問い合わせフォーム探索、競合・移動販売・デモ店舗の除外
- 今回直したこと：AI判定の格上げ禁止、URLエンコード、HTTP例外処理、1社ごとの途中保存、カフェ向けページ優先、営業リストと品質確認表の分離
- まだ直していないこと：PDFメニュー、埋め込み地図、許認可・認証を第4の必須ゲートにする処理
- 次回のテスト：カフェ以外の1業種を10社で試し、重要ページ語と誤分類パターンを追加する

### 2026-09-26｜一般工業用ネジ・タイ・卸／販売会社

- 調査候補：19社
- 最終出力：10社
- 機械判定：合格10社、確認待ち2社、対象外5社、取得不能2社
- 人の確認：10社中9社が「正しい」、1社が「間違い」で簡易チェック90%。Würth Industry Service (Thailand) は製造会社に見えるため対象外と判定された
- うまくいったこと：ネジ商品、販売・流通の役割、タイの拠点という3証拠を公式サイトから取得し、自社製造を明記する5社を合格リストから外した
- 難しかったこと：タイの検索結果には製造と販売を兼ねる会社が非常に多い。大手ホームセンターでは商品、会社概要、店舗・本社が別ページにあり、自動クロールがすべてをたどれない例があった
- 取得できなかったページ：RS ThailandとSUNRISEはBot対策等で公式サイト本文を取得できず、突破せず `blocked` にした
- 今回直したこと：候補追加、商品ページを入口にした再取得に加え、評価JSONへ全除外条件の明示チェックを必須化。チェック不足・判断不能は `review`、該当は `rejected` に下げるコードとテストを追加した
- まだ直していないこと：同一企業について人が指定した複数の証拠URLをクロールへ追加する仕組み、テンプレート由来の仮メール除外
- 次回のテスト：新しい除外チェック付き評価で同種の10社試験を行い、製造兼販売会社が意図どおり除外されるか確認する
